# 使用说明

一个运行在本机的中文 MVP 需求澄清与产品逻辑基线工具，面向**只有模糊想法、尚未想清楚产品细节**的个人构建者。用户描述设想，AI 整理草案和问题，关键决定由用户确认，最后保存一份经用户整体确认、包含产品规则与验收要求的 **Baseline v1**。

用户拥有产品决策权；AI 负责整理和审查，不判断功能必要性、商业价值或战略。

## 流程与范围

**产品设想 → MVP 梳理 → 最终确认**；提交后进入只读的**产品基线**，可以复制完整 Markdown 交给开发 Agent。

首页只必填 **描述你想象中的产品**（Product Concept / Experience Premise），项目名称可选。例如：“我想做一个自律监督工具，有玩偶随机巡查，离席会扣心。”不要求先填写 Description、Purpose、状态或完整规则。

必要问题按关联功能集中展示，无预选。问题目录提供已选／待选数量和跳转；选择只用于提交前汇总，不代表问题已解决。接受方案前展示关联功能、字段与当前／建议内容。通常提供完整 A/B/C 方案和 D 自定义；只有两个合理方案时 C 为“暂不确定”。缺少合理方案，或用户要求验收指标但没有给必要数值时，只提供 C 暂不确定与 D 自定义，可重新整理生成方案。先选择、查看汇总，再主动确认；所选决定一次保存，再按当前阶段继续 AI 审查，也可以只回答已想清楚的部分。

同一个业务决定可以同时影响多项审查，仍只需回答一题。已有草稿出现同义重复时，可点击“合并重复问题”，指定主问题并重新确认答案；原题与答复保留在历史中，合并后仍需审查。冲突与需要接受方案的问题不能合并。

全部必要问题保存在问题台账。部分回答、手动编辑或模型下次省略，都不会自动清除其他问题；答复保存后仍需审查。AI 使用后续用户资料关闭问题时，可展开“查看已解决问题与依据”。引用出处由程序核验，资料是否足以解决仍依赖 AI 判断；暂不确定继续阻塞。

- 初始功能确认前可调整；确认后全部 P0 保留来源和稳定标识。
- MVP 梳理主卡展示功能描述、简短验收和功能状态；完整规则、验收详情与审查依据可展开，已接受例外继续醒目展示，需要时手动编辑。
- 四个 Gate 分别保存清晰度、边界、直接一致性和可验证性的状态与依据，通常来自同一次模型请求；冲突解决规则作为独立建议，用户明确接受后才应用。
- 编辑使旧审查、预览和确认失效；提交前需完整阅读并整体确认。
- Agent、Human、Hybrid Verification 保存开发前验证要求与预期结果，不执行或伪造用户产品的测试结果。
- Verification 默认是个人 MVP 的最小充分验证：核心流程、已确认规则和影响结果的明显边界，优先现有界面、简单程序检查与必要真人实测。不会默认增加防欺骗、数据集、统计报告、大样本或生产指标；用户明确要求后才处理。
- Purpose 可以忠实归纳已有目标和功能，无法归纳时用自然语言询问；AI 空输出保留已有目的，用户主动清空仍有效。
- 首次提交生成只读 Baseline v1；可加入新功能继续生成 v2、v3…，每份快照保留，最新一份是当前产品基线。新项目保留旧项目。

**应用 V2 与 Baseline v1 是不同版本概念。** 应用版本以 [package.json](../package.json) 为准；应用升级不会重写旧基线，旧数据没有产品设定时显示“旧版本未记录产品设定”。

应用不开发用户产品、不访问用户代码仓库，不提供功能删除、历史回滚、增长或市场分析、云同步、团队协作、支付或本产品账号系统。支持完整基线文本复制和新增功能后的只读版本快照；文件下载导出尚未实现。仓库 AGENTS.md 用于维护本应用，不是产品生成物。

连接和模型可用时显示紧凑摘要，可展开调整设置；未配置或配置失效时直接展开。产品草案 Ready 后突出最终确认入口；完整预览末尾保留勾选与主动提交。基线页面区分当前有效版本、正在查看的历史快照和新增草稿，复制按钮及成功提示注明版本，正文保持原样。

未提交的首次设想、新功能设想与调整反馈在离开项目前会提醒确认，同一项目内切换页面保留输入；刷新或关闭页面也会提醒未保存内容。这些提醒不会自动保存或确认业务决定。名称超限时保留完整输入并标出字段。AI 审查显示当前阶段、等待时间与取消入口，失败后可主动重试本次审查；重试不重复提交已保存决定。

已有正式基线的项目在 AI 审查等待区可“查看当前有效基线”。独立只读面板展示并复制已经保存的当前快照，审查继续运行，写入与连接设置仍锁定；按 Esc 或点击关闭返回原工作页。请求完成时面板保留，关闭后查看工作页结果。

## 安装与启动

当前凭据适配器面向 **Windows**。先安装带 npm 的 Node.js，版本须满足 [package.json](../package.json) 的 `engines.node`。包管理器版本读取同一文件的 `packageManager`，在项目根目录执行：

```powershell
$taskPackageManager = (Get-Content ./package.json -Raw | ConvertFrom-Json).packageManager
npm install --global $taskPackageManager
pnpm install --frozen-lockfile
```

开发运行：

```powershell
pnpm dev
```

生产运行：

```powershell
pnpm build
pnpm start
```

浏览器打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。服务仅监听本机；使用 `127.0.0.1`，不要替换为 `localhost`，因为请求核验 Host、Origin 和 HttpOnly 会话。开发模式由 Vite 提供前端，后端修改会重新启动服务；按 `Ctrl+C` 停止。

`PORT` 调整端口，`BASELINE_DATA_DIR` 调整数据目录，默认数据目录相对启动工作目录解析。例如：

```powershell
$env:PORT = '3001'
pnpm start
```

启动命令使用 Node `--use-env-proxy` 读取已有受信任代理配置；未配置时直接连接。连接问题和认证保护详见 [AUTH_AND_MODELS.md](../AUTH_AND_MODELS.md)。

## AI 连接与模型设置

在 **AI 连接**选择 ChatGPT 账号、OpenAI API、DeepSeek API 或智谱 GLM API。主区域显示所选模型的实际 ID；思考开关和强度按模型能力提供。连接与目录读取时显示加载状态，已选模型失效时需重新选择，不自动替换。

- **ChatGPT 账号**：展开“管理连接”，点击官方 **Continue with ChatGPT**，由本人完成登录和 Plan Usage 授权。Connected 表示身份已连接；Using ChatGPT plan 表示已取得额度使用权限。保留添加、切换和退出多个账号的能力。
- **三种 API**：在“管理连接”的密码框填写该厂商标准 API Key，点击保存，再主动选择模型。每家保存一份 Key，可更换或移除；切换连接不退出其他账号、不删除其他 Key。
- **测试连接**：用户点击后执行一次小型结构化模型请求，消耗所选厂商 API 额度。保存 Key 不发起推理；“已配置”“验证成功”“连接失败”分别显示，验证只对应当时测试的模型。
- 模型请求运行期间不能修改连接、Key、账号或模型设置。新设置只作用于后续请求，失败不自动切换厂商、模型或连接，也不自动重试。

Key 提交后输入框清空，由后端使用 Windows DPAPI 加密保存在本机；前端不回显，不保存在浏览器存储。首次 API 连接必须选择模型；已有 ChatGPT 自动设置会保存为当前实际模型 ID，已有手动选择继续保留。OpenAI、DeepSeek 从官方模型目录读取，GLM 首批提供官方文档确认的 `glm-5.2`、`glm-5.3`；目录展示不代表账号已获模型权限。

登录不会授予读取 ChatGPT 对话或记忆的权限。AI 整理需要联网，将当前项目需求和澄清上下文发送至所选模型厂商；连接、网络、模型或额度错误保留已有草稿，可主动重试或取消。只支持三家官方标准 API 地址，不支持中转、自定义地址、GLM Coding Plan 或供外部脚本调用的产品 API。

具体协议、能力、等待上限与凭据保护见 [AUTH_AND_MODELS.md](../AUTH_AND_MODELS.md)。

## 使用与交给 Agent

1. 描述设想并点击“保存设想并开始”；未连接时先保存，连接后继续。
2. 阅读 AI 整理，回答必要的整体问题，可主动调整产品定义、场景、核心设定与初始功能。
3. 点击“确认这些设定与初始功能”，建立稳定 P0，并生成结构化定义与全局审查。
4. 在 **MVP 梳理**阅读功能卡片，用“处理问题”跳到关联题目。选择答案后点击“查看所选决定”，核对汇总，再确认；有冲突建议时完整阅读并主动接受解决规则。
5. 调整需求可用“告诉 AI 我想调整什么”，或展开“查看完整定义”进入手动编辑。已接受例外的修改或撤回需明确确认，再重新审查。
6. 当前审查有效、全部 Gate 通过、P0 字段与验收完整且问题台账全部已解决后，进入 **最终确认**。阅读设定、全部规则与验收，勾选“这就是我希望实现的第一版 MVP 产品逻辑。”，点击“确认并生成 Baseline v1”。
7. 在 **产品基线**点击 **复制给 Agent**，直接粘贴给 Codex 或其他开发 Agent。用“新建项目”和项目下拉框管理独立项目。

复制包含项目名称、Baseline v1、提交时间、产品定义、场景、设定、全部 P0 的稳定标识、描述、意图、生效条件、规则、已确认例外和适用验收字段，以及固定简短交付说明。用户确认的量化要求也完整复制。它使用已保存原文，不调用 AI，不包含工作对话、审查状态、问题台账、来源/关闭依据、未接受建议或认证信息。

只有剪贴板写入成功才提示已复制；浏览器拒绝时展开同一完整文本，点击“选中全文”后按 `Ctrl+C`，手机可长按复制。复制不会修改项目。

若提示草稿或建议已失效，重新读取保存状态并审查；旧预览不能提交新内容。已确认保存的答案和规则在 AI 更新失败后仍保留，未提交的选择按项目和修订号暂存，修订变化后清除。

量化验收显示指标、门槛和样本要求，未约定值显示“未定义”。没有提出指标不会因此阻塞；明确要求指标却缺少必要门槛时，需要自定义回答，不能以“未定义”完成验收。模拟测试输入可以构造；指标和样本规模必须有本项目用户资料来源，不能来自旧 AI 建议。后端拦截常见无来源指标、空泛预期和不完整选项，但没有穷尽自然语言表达。

## 提交后加入新功能

在产品基线点击“加入新功能”，可一次描述多项能力。AI 逐项说明独立新 P0 或已有 P0 补充；确认完整清单后建立稳定编号，进入独立的“新旧功能确认”。确认前可修改设想重新判断。

“新旧功能确认”检查旧与新、新增之间及同一 P0 内的冲突、生效条件、边界和产品实现约束。具体方案列出双方要求及要改变的规则，选择后集中查看汇总并明确接受；自定义回答须先整理成方案再接受。无冲突且无需改旧规则时直接进入完整 MVP 梳理。未受影响字段和验收保持原文，规则改变重新定义验收；全部 P0 重新接受同样的四 Gate 与问题台账审查。

审查未成功时显示等待/失败和重试，不提供占位业务问题。合理方案优先 A/B；缺少必要信息时说明缺什么，旧方案失效时说明需重新生成。已有失败新增草稿保留编号、原文和答复，恢复到新旧关系审查；不会自动拆分已经确认的功能，要重新拆分可放弃本轮并重新发起新增。

最终确认先展示与当前基线的差异，再展示完整新产品预览。勾选“这就是我希望更新后的当前产品逻辑。”并提交，才生成下一版本并成为当前基线；草稿期间旧基线继续有效。可随时阅读和复制当前基线，也可“放弃本次新增”恢复已提交内容。每项目同时只有一份新增草稿；已保存草稿可刷新、重启恢复。

提交新版本后，“查看基线版本”可阅读和复制各历史快照。选择历史快照不会回滚当前产品；再次新增始终基于最新当前基线。已提交快照不可直接编辑、重置或删除。

## 本地数据与重置

默认在启动目录的 `data/` 保存，目录被 Git 忽略：

| 数据 | 位置 |
| --- | --- |
| 产品工作资料与正式基线 | `data/baseline.sqlite`，分层说明见 [ARCHITECTURE.md](../ARCHITECTURE.md) |
| SQLite 运行文件 | `data/baseline.sqlite-wal`、`data/baseline.sqlite-shm`，运行期间可能存在 |
| OS 加密保护的 ChatGPT 连接 | `data/auth/chatgpt-auth.json` |
| OS 加密保护的 API Key、当前连接与模型偏好 | `data/auth/model-api-keys.json`，独立于 ChatGPT 凭据 |
| 稳定安装 host ID，非凭据 | `data/auth/chatgpt-host.json` |

正式基线只保存确认的产品内容、验收要求、版本和时间；原始设想、聊天、临时审查和建议属于独立工作资料。产品数据库没有额外应用级加密，OAuth 凭据与 API Key 由 Windows DPAPI 分别保护，并绑定当前 Windows 用户。

- **重置设想整理**：保留当前保存的原始设想，清除未确认的整理、回答和问题台账。
- **重置草稿**：保留背景、初始 P0 来源和标识，清除当前未提交项目的整理、验收、已接受例外、对话、审查、问题台账和指标来源；已提交项目不能重置。
- **新建项目**：保留旧项目和只读基线。
- **完全清空产品数据**：仅在本人确实需要删除全部项目时，停止服务、备份后手动删除 SQLite 文件及其运行文件。浏览器若记住已删除项目，可点击“新建项目”。测试和升级不能用这个方式处理数据。
- **退出账号**：使用 **Sign out**，不要删除 `data/auth/` 代替退出，以免丢失 host 和注册映射或未完成远程撤销。

本机文件不参与 ChatGPT 云同步。备份与恢复时保留完整产品数据；复制认证加密文件到另一用户或机器不能直接复用连接。

## 在独立 worktree 开发

Git worktree 共享提交历史和分支，工作文件、依赖与默认 `data/` 目录分别位于各自工作目录。新 worktree 需要在该目录安装依赖、构建后运行；忽略目录和未提交文件不会自动从原目录复制。数据目录和认证位置仍按启动工作目录及 `BASELINE_DATA_DIR` 解析，不因共享 Git 历史自动共享产品数据或登录状态。

若原应用仍在 3000 端口运行，可在新工作目录使用独立端口，例如：

```powershell
$env:PORT = '3001'
pnpm build
pnpm start
```

默认使用该工作目录自己的 `data/`。开发测试遵循 [VALIDATION.md](../VALIDATION.md) 的隔离规定；不要通过复制认证文件或共用正式数据库来绕过隔离。

## 已知限制与 Future Work

LLM 的语义审查不是形式化证明；结构校验保护数据与提交约束，不能保证模型绝不遗漏问题，用户仍需阅读最终预览。Local-first 不等于离线 AI，真实资格、额度和模型兼容性取决于官方服务，失败时不更换授权方式。

已提交快照不可直接修改；新增功能可形成新版本，功能删除与历史回滚尚未实现。当前没有安装包或开机启动，DevKit 再分发需遵守 [vendor/README.md](../vendor/README.md) 及各许可证。

升级只导入仍存在的问题，不恢复历史已丢失的问题。旧 Review 缺新元数据时须重新审查后提交，功能显示待整理；旧 Baseline 原样保留。后续可另行评估跨平台凭据适配、Baseline 文件下载导出和独立设计的变更流程；这些不属于当前范围。
